# Local UI: minimalist, micro detailed, complete

Spec ID: 008
Status: implemented, independent audit owed (see Status below)
Branch: feature/v1-gateway
Depends on: specs 001, 002, 003, 004, 005 and 006 for the surfaces it exposes.

## Objective

The UI is the surface the client judges. It must be extremely minimalist and, at the same time, complete: nothing decorative, nothing missing, and the two product distinctions (a provider is not a credential, a catalog is not a policy) visible on screen instead of hidden in a paragraph.

## Principles

- Atomic Lazy Design with three layers only: atoms, molecules, organisms. Nothing subdivided further.
- `theme/tokens.css` remains the single source of design tokens. No hardcoded color, spacing, radius, font size or duration in a component.
- No UI library. Fragments are adapted into the repository when a primitive is genuinely needed.
- Honest states everywhere: loading, empty, error, degraded and partial. Every state is designed, not defaulted.
- Keyboard first: the whole flow from zero credentials to an exposed model is completable without a mouse, with a visible focus ring and a sensible tab order.
- Density without clutter: small type scale, generous whitespace, data aligned in columns, no card inside a card.

## Screens

1. Estado: gateway health, version, uptime, database path, provider count, exposed model count, last provider errors.
2. Credenciales: add with namespace, provider, base URL and secret; per credential validate, refresh, rotate secret and see the hint, the catalog count and the last refresh error.
3. Catalogo y exposicion: the two lists side by side, with search, per model allow and deny, the effective rule shown per row, and the count of discovered against exposed.
4. Modelos expuestos: the namespaced identifiers ready to copy into a client configuration.
5. Ajustes: port, database path, theme tokens, language switch placeholder, and the pepper warning before the first secret is saved.

## Micro detail passes

Three focused passes, each one its own commit, in this order:

1. Structure and semantics: landmarks, headings, labels, table semantics, focus order, and no div where a button belongs.
2. States and micro interactions: hover, active, focus visible, disabled, busy, copy feedback, destructive confirmation, error text that says what to do next, empty states with one clear next action.
3. Visual polish: rhythm, alignment, contrast, truncation with tooltip for long model names, number and date formatting, reduced motion, and no layout shift when data arrives.

## Acceptance criteria

- [x] No hardcoded design value outside `theme/tokens.css`, proven by a grep in the check. Verified by enumeration over the 66 source files of the interface (zero hits for hex, px, rem, em, rgb, cubic-bezier and ms outside the token file), and by a committed test that fails when a stylesheet uses a `var()` that is not defined.
- [x] Every screen above exists and every state (loading, empty, error, degraded) is implemented and reachable. Five routes exist (`/`, `/credenciales`, `/catalogo`, `/modelos`, `/ajustes`, all in the build output), and `ResourceState` renders loading, failed with nothing, failed over a reading still on screen (degraded) and empty with its next action.
- [ ] The zero to exposed model flow is completed with the keyboard only. Structurally verified (links and buttons only, no clickable div, one global `:focus-visible` rule, no focus trap, the confirmation returns focus to the control that opened it), never walked in a live browser: that was the audit's job and the audit did not run.
- [ ] Focus is always visible and never trapped; the tab order follows the visual order. Same as above: one global focus rule and no `outline: none` anywhere, verified structurally, not walked in a browser.
- [x] Contrast meets WCAG AA for text and interactive elements, checked with a tool, not by eye. `apps/frontend/src/theme/contrast.spec.ts` measures the 30 pairs the interface paints (text at 4.5, control boundaries and focus rings at 3) from the tokens themselves. Proved red before green: lowering `--color-content` fails the case, and the file was restored byte identical, verified by hash.
- [x] The two catalog and exposure counts are always on screen together, so the distinction cannot be missed. `CatalogPanel` renders both counts in one `MetaList` above the table, and the sentence under the table says the rules live in the gateway and are not evaluated by the panel.
- [x] A secret is never rendered, only its hint, and the copy action never puts it in the clipboard. The only clipboard call in the interface writes a model identifier; the credential row renders `secretHint`; the rotation keeps the typed secret in local state, drops it when the confirmation closes and never puts it in the store.
- [ ] No layout shift when data arrives, and no request waterfall beyond one call per panel. The waterfall is verified (one call per resource on mount, in one provider, no fetch during render). The layout shift is not: it needs a browser, and the reserved space tokens are only the structural half of it.
- [x] The three passes are separate commits with their own before and after evidence. `04a7f5b`, `4704211` and `6e978ec`, each with the lane's before and after report; the third keeps its measuring script as the committed test above.
- [ ] An independent audit re-checks each criterion and reports what it could not verify visually. NOT DONE, and not downgraded to a self review: the audit lane failed twice with `Unauthorized` (runs run_00004, run_00005 and run_00006), which is an account level failure the user has to clear by re-authenticating Cline. The three passes were reviewed by the coordinating session, which is not independent, and that review is what the other ticks above record.

## Risks

- Minimalism that turns into cramped or cryptic is a failure, not a style. The density rule is checked at each pass.
- Hiding the policy behind a toggle would contradict the product's own thesis, so exposure decisions stay visible per row.
- A UI that fetches on every render turns a local gateway into a slow app. One call per panel, cached in the hook, refreshed on demand.

## Status

Implemented on 2026-09-30 in the three passes the spec asks for, one commit each: structure and semantics (`04a7f5b`), states and micro interactions (`4704211`), visual polish and measured contrast (`6e978ec`). The evidence bar of the project is green: typecheck of the four workspaces, 345 backend tests, 19 command line tests, 17 interface tests, the build of every workspace and the 27 case end to end run. A separate commit (`aa606ee`) gave the interface the rotation of a secret, because pass 1 found the gateway endpoint existed and the interface did not expose it, and the panel had disabled the action instead of faking it.

What the third pass changed in the product, beyond the criteria: the contrast of the control boundaries. Pass 2 bounded the inputs and the secondary button with `--color-border` and `--color-border-strong`, which are separators, not control boundaries: the input boundary measured 1.29:1 against its surface. Two control tokens were added with the requirement written next to them (3:1), and the same measuring script that proved it now runs as a test, so the next change to a colour fails the suite instead of shipping a boundary nobody can see.

Open, and deliberately not closed here: the independent audit. The lanes failed with `Unauthorized` three times (run_00004, run_00005, run_00006) and that is an account level failure to clear by re-authenticating Cline, not something the coordinating session can work around. Without it, criteria 3, 4 and 8 keep their structural evidence only, and criterion 10, the audit itself, stays unticked. That the keyboard walk and the layout shift need a browser is the honest half of it.

Reading a live API is out of scope for this version, in writing, because spec 008 owns the question that spec 013 left open:

- The interface talks to the gateway through `services/api/`, and every one of those modules is a thin shape over `fetch`. What could break there is the shape, not the transport, so the suite injects the transport and asserts the shape (17 cases: the error mapping of the client and the path, method and body of every call).
- The end to end run does not start Next, so a test that rendered a screen would need a second runtime (a browser or a DOM), and the whole value of that test would be in asserting what the gateway already answers: the same data the end to end run exercises over a real socket, one layer up.
- What only a browser can check is exactly the list that stays open above, and no unit test replaces it; making the suite pretend otherwise would be theatre. The honest closure is the audit, by a person or a lane, with the app running.
